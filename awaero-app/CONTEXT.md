# Context for Claude Code: awaero-app

Read this first, then `PROGRESS.md`. Keep replies short and practical.

## What this app is
**Awaero**, the phone app for the FYP (vision-based smart power management).
It is the native twin of the local web dashboard (`../web-dashboard`, also
called Awaero) and reads the same server, `../state_server.py`, on Amir's Mac.

It was created 2026-11-16 as a COPY of `../app-monitor`, on Amir's instruction
to make a new app and not disturb the old one. So:

- `../app-monitor` is the OLD app. Do not edit it from here. It is still
  installed on the phone as "app-monitor" (`com.amiryzat.app-monitor`).
- This folder is the NEW app, "Awaero" (`com.amiryzat.awaero`). Both sit on the
  phone side by side and keep separate settings.

## Stack
Expo SDK 58, React Native 0.88, TypeScript, Expo Router. Native builds only
(no Expo Go): `ios/` is generated by prebuild and is gitignored. See `AGENTS.md`
for the Expo rules.

## The data it shows
Everything comes from `state_server.py` over the local network, port 8000:
`/health`, `/state`, `/history`, `/metrics`, `/frame.jpg`, `/trials`.
No cloud, no account. `src/lib/state.ts` mirrors the server's JSON; the web
dashboard's `src/lib/types.ts` is the same contract. Change all three together.

`PRD.md` is the original spec (copied from app-monitor). It predates the
5-appliance policy and the server-scored Trials recorder; where it disagrees
with `state_server.py`, the Python wins.
